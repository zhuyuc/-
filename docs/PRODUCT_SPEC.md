# 本地模拟交易系统产品文档

版本：V1.0
状态：产品方案
适用市场：A 股（上交所、深交所、北交所）与港股（港交所）

## 1. 产品定位

本产品是一个本地运行的 A 股、港股模拟交易记录和持仓分析工具。系统不执行真实下单，联网只用于股票名录和行情，交易及分析数据保存在本机。
## 2. 产品范围

### V1 必须实现

- 本地账号创建、登录、切换和锁定。
- 市场固定计价币种：A 股统一使用 CNY，港股统一使用 HKD。
- 每个账号独立、加密的本地数据文件。
- 搜索上交所、深交所、北交所 A 股和港股。
- 买入、卖出、交易记录，以及可选的持仓成本分摊方法。
- 按市场、交易所、买卖方向和生效日配置费用。
- 每日保存持仓股票的最后成交价。
- 持仓市值、已实现盈亏、未实现盈亏和趋势图。

### V1 不包含

- 真实下单、撤单、资金划转或券商登录。
- 自动读取券商交割单、自动云同步、融资融券、期权和利息。
- 自动识别分红、送股、拆股、配股等公司行为。

公司行为后续作为独立事件处理；V1 提供手动调整入口并提示影响。
## 3. 业务口径

用户填写的成交单价是每股价格，成交金额由系统按「成交单价 × 成交数量」自动计算，为未含费用的毛成交额。市场直接决定计价币种：上交所、深交所、北交所 A 股统一使用人民币（CNY），港交所港股统一使用港币（HKD）。例如输入单价 `10.00`、数量 `1,000`，系统必须明确显示成交金额为 `CNY 10,000.00` 或 `HKD 10,000.00`，不能只保存数字。

~~~text
成交金额 = 成交单价 × 成交数量
买入持仓成本 = 毛成交额 + 各项买入费用
卖出净收入 = 毛成交额 - 各项卖出费用
~~~

“最后价格”严格指数据源提供的最后成交价。每条行情保存交易日期、最后成交时间（数据源提供时）、价格、数据源、本机获取时间和状态。数据源只提供收盘价时，页面必须标为“收盘价”，不能标成“最后成交价”。

A 股所有成交、费用、成本和盈亏均使用 CNY；港股所有成交、费用、成本和盈亏均使用 HKD。两个市场分别汇总，不直接相加。V1 只支持这两种固定币种的普通 A 股和港股交易，不在逐笔交易中引入汇率；港股通等跨币种业务作为后续独立市场模板处理。

## 4. 账号与本地数据

系统采用本地账号，不依赖云端账号。全局索引只保存账号 ID、用户名、密码派生校验值、数据库文件位置、创建时间和最后登录时间，不保存财务数据。

每个账号拥有一份独立加密 SQLite 数据库，保存交易、费用规则和费用快照、股票名录副本、每日行情、持仓快照、成本分摊方法、图表配置、操作日志和备份元数据。
### 账号隔离规则

- 登录后只打开当前账号数据库。
- 切换账号时关闭连接，清空内存中的交易、持仓、行情和搜索结果。
- 所有查询和写入都通过当前会话的数据库句柄执行。
- 任意账号不能读取、搜索或导出其他账号的数据。
- 自动锁定后关闭连接并清理页面状态。

本地加密保护未解锁数据，但不能替代操作系统账户安全。本机管理员仍可能访问设备文件。

### 用户流程

~~~text
启动应用 → 选择或创建账号并登录 → 配置费用规则
→ 搜索股票 → 选择买入/卖出 → 填写数量和成交单价
→ 自动计算费用、成本或净收入 → 查看持仓和趋势
→ 登录后更新行情并保存到本地
~~~

## 5. 页面设计

### 5.1 持仓总览

首页按市场币种分别展示 CNY 与 HKD 持仓小计；A 股只出现在 CNY，港股只出现在 HKD。字段包括股票、代码、交易所、市场、币种、数量、剩余成本、最后成交价、价格日期、市值、未实现盈亏和盈亏率。不得把不同币种金额放进同一个合计数。
~~~text
┌────────────────────────────────────────────────────────────┐
│ 我的账号                         [记录交易] [更新行情] [锁定] │
├────────────────────────────────────────────────────────────┤
│ CNY 持仓（A 股）                    HKD 持仓（港股）             │
│ 市值 ¥52,400  浮盈 ¥2,180          市值 HK$31,800 浮盈 -620  │
│ 搜索当前持仓...        [全部] [A股] [港股]                    │
│ 股票/市场       数量   剩余成本   最后成交价   市值   浮动盈亏 │
│ 平安银行 000001.SZ 1000 ¥10.20   ¥10.80       ¥10800 +¥600 │
│ 腾讯控股 00700.HK  100  HK$310   HK$318       HK$31800 +800 │
│ 平安银行 · 最后成交价趋势      [本月] [3个月] [半年] [1年] [全部] │
│                         折线图                               │
└────────────────────────────────────────────────────────────┘
~~~

趋势图使用每日最后成交价，支持本月、近 3 个月、近半年、近 1 年和全部。首次加入股票时，在数据源允许的范围内补取历史价格；缺失交易日显示空白。

### 5.2 记录交易

交易页面只要求填写股票、方向、数量和成交单价（每股）；成交金额由系统按单价 × 数量自动计算，费用字段不由用户填写。选择股票后自动确定市场币种：A 股显示 `CNY`，港股显示 `HKD`。成交金额、单价、每项费用、买入总成本或卖出净收入全部使用同一币种，不提供换汇输入。

~~~text
[买入] [卖出]  市场 [全部]  搜索代码、中文名、拼音或英文名...
结果：000001.SZ 平安银行 深交所·A股·CNY
      00700.HK 腾讯控股 港交所·港股·HKD
已选：平安银行 000001.SZ
成交日期 [2026-09-24]   数量 [1,000] 股
成交单价（每股） [CNY 10.00] → 成交金额 CNY 10,000.00（数量 1,000 自动计算）
单价（自动）CNY 10.00   交易费用（自动）CNY 5.10
买入总成本 CNY 10,005.10             [确认保存]
~~~

保存前默认展开逐项费用计算；交易明细显示各项费用与合计（金额为 0 的项目标「未收取」，参考券商对账单），并显示实际收付。每项费用均使用股票所属市场的币种。卖出数量不能超过可卖数量。每笔卖出的已实现盈亏在概览「累计已实现盈亏」与看板卡片中按币种呈现，不在交易表逐行单列。
搜索覆盖上交所、深交所、北交所 A 股和港股。A 股支持代码、中文名、拼音；港股支持代码、中文名、英文名和拼音。结果显示代码、名称、交易所、市场和固定币种。港股通等跨币种品种在 V1 中标记为暂不支持，不进入普通港股交易录入。

### 5.3 交易记录

支持按股票、市场、买卖方向和日期筛选，按成交日期倒序展示。展开一笔交易查看逐项费用、规则版本、计算过程、总成本或卖出净收入。支持修改和撤销；操作后从该日期重新计算持仓、成本和盈亏，并记录审计日志。

### 5.4 费用设置

费用设置不是只保存一个费率，而是保存一条可以执行的计算规则。每个费用项必须记录以下字段：

| 字段 | 说明 |
|---|---|
| 计费基数 | 毛成交额、数量或固定每笔 |
| 计费方式 | 比例、固定金额、比例加最低收费、比例加最高收费 |
| 币种 | 由市场自动带出：A 股为 CNY，港股为 HKD，用户不能修改 |
| 费率单位 | 百分比（%）、千分比（‰）或万分比（‱） |
| 方向 | 买入、卖出或双向 |
| 最低/最高收费 | 按每笔成交还是按订单；默认按每笔成交 |
| 取整规则 | 不取整、四舍五入到分、向上取整到元等 |
| 包含关系 | 是否已经包含在佣金或其他费用中 |
| 生效时间 | 费用规则开始生效的日期和时间 |
| 券商转嫁 | 费用由券商承担、转嫁或按交割单确定 |

~~~text
[沪市A股] [深市A股] [北交所A股] [港股]
当前：沪市 A 股 · 普通股票           生效日期 [2026-09-24]

项目             买入设置                 卖出设置
券商佣金         比例 [0.03%] 最低 [5元]  比例 [0.03%] 最低 [5元]
交易经手费       已包含在佣金             已包含在佣金
证管费           已包含在佣金             已包含在佣金
过户费           比例 [0.01‰]             比例 [0.01‰]
印花税           不收取 [0]               比例 [0.5‰]
券商其他费用     不收取 [0]               不收取 [0]

每项可切换：不收取（0） / 固定金额 / 按比例 / 已包含
                                              [保存并启用规则]
~~~

交易页必须显示费用明细，但用户不需要逐项输入。每笔交易保存规则版本、输入参数、逐项计算结果和最终扣减；规则改动只影响之后的交易。沪深北的小数取整如果因券商不同而不同，必须按券商交割单配置，不能写死为一个市场统一规则。上方示例中的 0.03% 佣金只是演示值，正式值由用户填写。

### 5.5 按市场逐项填写的费用清单

用户进入某个市场的费用设置后，系统只展示该市场适用的费用项目。每一行都必须填写“0”或一个具体金额/比例；空白不允许保存。对于比例项目，用户可以直接输入 `0.03%`、`0.1‰` 等形式；对于固定项目，输入金额，例如 `5.00`。买入和卖出分别填写，系统不把“0”理解成尚未配置。

每一行有四种可选状态：`按比例`、`固定金额`、`不收取（0）`、`已包含在佣金中`。选择“按比例”时可设置最低/最高收费；选择“固定金额”时该金额每笔收取一次；选择“不收取（0）”时无需再输入费率；选择“已包含”时展示参考规则，但本笔额外扣减为 0。所有适用项目都明确填完后才允许启用该市场费用模板。

#### 沪市 A 股、深市 A 股

| 费用项目 | 买入 | 卖出 | 默认计算方式 |
|---|---:|---:|---|
| 券商佣金 | 输入比例/固定额 | 输入比例/固定额 | `max(毛成交额 × 佣金率, 每笔最低佣金)`；佣金上限和最低额按券商合同 |
| 证券交易经手费 | 0 或输入比例 | 0 或输入比例 | 毛成交额 × 0.0341‰；通常已包含在券商佣金中，不能重复计算 |
| 证管费/证券交易监管费 | 0 或输入比例 | 0 或输入比例 | 毛成交额 × 0.02‰（即 0.002%）；通常已包含在券商佣金中，不能重复计算 |
| 过户费 | 输入比例/固定额 | 输入比例/固定额 | 毛成交额 × 0.01‰，买卖双向 |
| 证券交易印花税 | 0 | 输入比例 | 毛成交额 × 0.5‰，卖出单边 |
| 券商其他费用 | 输入金额/比例 | 输入金额/比例 | 按交割单填写；没有则填 0 |

沪深普通 A 股的“经手费”和“证管费”若已包含在券商佣金中，选择“已包含在佣金中”，额外扣减为 0；如果券商交割单将它们单独列出，取消包含关系并填入比例。佣金的最高 3‰、最低 5 元见上交所投资者说明，具体仍按券商合同配置。

#### 北交所普通股票

| 费用项目 | 买入 | 卖出 | 默认计算方式 |
|---|---:|---:|---|
| 券商佣金 | 输入比例/固定额 | 输入比例/固定额 | `max(毛成交额 × 佣金率, 券商最低佣金)`；最低额不预设，按券商合同 |
| 北交所交易经手费 | 输入比例 | 输入比例 | 毛成交额 × 0.125‰，买卖双边；协议转让单方每笔最高 10 万元 |
| 过户费 | 输入比例/固定额 | 输入比例/固定额 | 毛成交额 × 0.01‰，买卖双向 |
| 证券交易印花税 | 0 | 输入比例 | 毛成交额 × 0.5‰，卖出单边 |
| 券商其他费用 | 输入金额/比例 | 输入金额/比例 | 按交割单填写；没有则填 0 |

北交所经手费单独列项；如果券商佣金已包含该费用，则标记“已包含在佣金中”，额外扣减为 0。北交所其他费用按券商交割单单独配置。协议转让的 10 万元上限不套用普通竞价交易。

#### 港股直接交易（港交所）

| 费用项目 | 买入 | 卖出 | 默认计算方式 |
|---|---:|---:|---|
| 券商佣金 | 输入比例/固定额 | 输入比例/固定额 | `max(毛成交额 × 佣金率, 券商最低佣金)`；佣金自由协商 |
| 证监会交易征费 SFC | 输入比例 | 输入比例 | 毛成交额 × 0.0027%，每边按港币 0.01 元四舍五入 |
| 会财局交易征费 AFRC | 输入比例 | 输入比例 | 毛成交额 × 0.00015%，每边按港币 0.01 元四舍五入 |
| 港交所交易费 | 输入比例 | 输入比例 | 毛成交额 × 0.00565%，每边按港币 0.01 元四舍五入 |
| 股票印花税 | 输入比例 | 输入比例 | 毛成交额 × 0.1%，买卖双方均收，分别向上取整到港币 1 元 |
| 投资者赔偿征费 | 0 | 0 | 当前暂停，买卖两侧默认均填 0；恢复征收时建立新规则版本 |
| HKSCC 股份交收费 | 0 或输入比例 | 0 或输入比例 | 毛成交额 × 0.0042%，是否转嫁由券商决定；转嫁规则按交割单配置 |
| 纸质过户文据印花税 | 0 | 0 或固定 HK$5 | 仅登记/纸质过户场景，普通电子成交默认 0 |
| 股票登记过户费 | 0 或固定 HK$2.50 | 0 | 仅新股票证书等登记场景，普通电子成交默认 0 |
| 券商其他费用 | 输入金额/比例 | 输入金额/比例 | 按交割单填写；没有则填 0 |

港股直接交易在 V1 中统一按 HKD 计价、计算费用和记录成本。港股通等跨币种业务不复用本模板，后续作为独立市场模板增加；在启用前必须单独确认其市场币种和券商收费口径。

### 5.6 交易页的费用明细

用户点击“确认保存”前，费用区域必须展开为逐项结果，而不是只显示一个费用总额：

~~~text
毛成交额                                      ¥10,000.00
券商佣金  max(10,000 × 0.03%, 5.00)              ¥5.00
过户费    10,000 × 0.01‰                         ¥0.10
经手费    已包含在佣金                              ¥0.00
证管费    已包含在佣金                              ¥0.00
印花税    买入不收                                  ¥0.00
费用合计                                         ¥5.10
买入总支出                                  ¥10,005.10
~~~

如果用户将某一项填为 0，页面明确显示“未收取：¥0.00”；如果规则来自佣金包含关系，显示“已包含：¥0.00”，两者不能混淆。

一条交易记录原则上对应一张交割单/成交确认单。若一笔委托分多次成交，佣金最低收费、港股印花税和其他按笔费用可能按券商合单口径计算；费用规则需设置“每次成交”或“合并订单”计费单位，并保留券商订单号供核对。

同样以毛成交额人民币 10,000 元卖出沪深 A 股，假设佣金率 0.03%、每笔最低 5 元、经手费和证管费已包含佣金、过户费 0.01‰，则佣金 5 元、过户费 0.10 元、印花税 5 元，费用合计 10.10 元，卖出净收入 9,989.90 元。实际取整仍以该用户配置的券商规则为准。

以毛成交额港币 100,000 元交易普通港股为例，买入和卖出的 SFC 征费均为 2.70 元、AFRC 征费 0.15 元、港交所交易费 5.65 元、股票印花税 100 元。若券商转嫁 HKSCC 股份交收费，再加 4.20 元；券商佣金和其他费用按用户配置另计。未计佣金及其他费用时，不转嫁结算费的单边费用为 HK$108.50，转嫁时为 HK$112.70；卖出同额的净收入分别为 HK$99,891.50 与 HK$99,887.30。
## 6. 费用和盈亏计算

默认模板覆盖沪深 A 股佣金、过户费、卖出印花税和规费包含关系；北交所独立交易经手费和相关税费；港股佣金、交易费、交易征费、财汇局征费、股票印花税及由券商决定是否转嫁的结算费。

费用引擎先按交易日期选择生效规则，再按市场、交易所和方向筛选费用，计算费率或固定费用，应用最低/最高收费和取整规则，最后处理佣金包含关系。交易所和税务机关公布收费项目与费率；下面的持仓成本分摊方法是本产品的记账选择，不是交易所规定的统一盈亏算法。

查阅截至 2026-09-24 的公开规则后，各市场的计算边界如下：

| 市场 | 官方规则覆盖的计算 | 个人持仓成本和部分卖出盈亏 |
|---|---|---|
| 上交所 A 股 | 成交价格、成交数据、交易所费用及相关代收税费 | 未见交易所指定移动加权平均或 FIFO |
| 深交所 A 股 | 成交价格、成交数据、交易所费用及相关代收税费 | 未见交易所指定移动加权平均或 FIFO |
| 北交所 A 股 | 成交价格、成交数据、交易所费用及相关代收税费 | 未见交易所指定移动加权平均或 FIFO |
| 港交所港股 | 成交与结算、交易费、征费和印花税等逐笔费用 | 未见港交所指定移动加权平均或 FIFO |

因此，“与交易所一致”指成交金额、适用费率、计费方向、最低收费及取整等官方规则；券商佣金、结算费转嫁和部分取整还需以实际券商交割单为准。持仓成本价和盈亏须明确标为“系统核算口径”，不能声称是“交易所盈亏”。参考：[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)、[北交所交易规则](https://www.bse.cn/jygl_list/200028217.html)、[港交所交易费用](https://www.hkex.com.hk/Services/Rules-and-Forms-and-Fees/Fees/Securities-%28Hong-Kong%29/Trading/Transaction?sc_lang=en)。

每一个费用项目先单独计算、按该项目规则取整，最后再汇总。港股交易所项目按官方规则执行；A 股各项目的券商实际取整顺序按交割单配置。统一计算函数如下：

~~~text
不收取：原始费用 = 0
固定金额：原始费用 = 每笔固定金额
按比例：原始费用 = 计费基数 × 费率
比例+最低收费：原始费用 = max(计费基数 × 费率, 最低收费)
配置最高收费时：原始费用 = min(原始费用, 最高收费)
已包含在佣金中：额外扣减 = 0，同时显示“已包含”
其他情况：最终费用 = 按该项目取整规则处理原始费用
本笔费用合计 = 各项目最终费用之和
~~~

市场模板的实际默认值如下；用户可以改成自己的券商收费，也可以将某一项设为 0：

~~~text
沪/深 A 股买入：
  佣金 = max(毛成交额 × 佣金率, 最低佣金)
  过户费 = 毛成交额 × 0.01‰
  经手费 + 证管费 = 0（若已包含在佣金；若交割单单列则按 0.0341‰ + 0.02‰ 计算）
  印花税 = 0

沪/深 A 股卖出：
  佣金、过户费同买入
  印花税 = 毛成交额 × 0.5‰

北交所普通股票：
  佣金 = max(毛成交额 × 佣金率, 券商最低佣金)
  交易经手费 = 毛成交额 × 0.125‰（买卖双边；佣金已包含时额外扣减为 0）
  过户费 = 毛成交额 × 0.01‰（买卖双边）
  印花税 = 0（买入）或毛成交额 × 0.5‰（卖出）

港股直接交易：
  佣金 = max(毛成交额 × 佣金率, 券商最低佣金)
  SFC = 毛成交额 × 0.0027%，每边四舍五入到 HK$0.01
  AFRC = 毛成交额 × 0.00015%，每边四舍五入到 HK$0.01
  交易费 = 毛成交额 × 0.00565%，每边四舍五入到 HK$0.01
  印花税 = 毛成交额 × 0.1%，买卖双方分别向上取整到 HK$1
  HKSCC = 毛成交额 × 0.0042%（只有券商转嫁时才计入）
~~~

沪深北费用的小数取整和最低佣金可能因券商合同而不同，必须可以按交割单覆盖。港交所公布的 SFC、AFRC 和交易费均为每边按分取整，股票印花税为买卖双方分别向上取整到港币 1 元。

费用规则的参考来源：[上交所 A 股交易费用](https://one.sse.com.cn/onething/gptz/)、[深交所收费标准](https://www.szse.cn/marketServices/deal/payFees/)、[北交所经手费公告](https://www.bse.cn/important_news/200018086.html)、[中国结算北京市场收费表](https://www.chinaclear.cn/zdjs/fbzyls/202506/69144099e23c436ab678b9d778260402/files/%E5%8C%97%E4%BA%AC%E5%B8%82%E5%9C%BA%E8%AF%81%E5%88%B8%E7%99%BB%E8%AE%B0%E7%BB%93%E7%AE%97%E4%B8%9A%E5%8A%A1%E6%94%B6%E8%B4%B9%E5%8F%8A%E4%BB%A3%E6%94%B6%E7%A8%8E%E8%B4%B9%E4%B8%80%E8%A7%88%E8%A1%A8.pdf)、[港交所交易收费](https://www.hkex.com.hk/Services/Rules-and-Forms-and-Fees/Fees/Securities-%28Hong-Kong%29/Trading/Transaction?sc_lang=en)、[港交所结算收费](https://www.hkex.com.hk/Services/Rules-and-Forms-and-Fees/Fees/Securities-%28Hong-Kong%29/Clearing-and-Settlement/Operational?sc_lang=en)。

~~~text
买入持仓成本 = 毛成交额 + 买入费用合计
卖出净收入 = 毛成交额 - 卖出费用合计
~~~

以上金额始终使用该股票所属市场的固定币种：A 股使用 CNY，港股使用 HKD。费用、成交、持仓成本、卖出净收入和盈亏之间不换汇；CNY 与 HKD 仅在首页分组展示，不直接相加。V1 不保存汇率，也不存在“待汇率计算”状态。

持仓成本分摊只在多次买入后部分卖出时产生差别。首版默认“移动加权平均”，是因为它能把历次买入成本和费用按当前持仓数量均摊，便于持续显示一个持仓单位成本；这只是所有市场统一使用的产品默认口径，不代表交易所或券商要求采用该算法。账号设置中可选“移动加权平均”或“先进先出 FIFO”。选择会影响每笔卖出的已实现盈亏及剩余持仓成本，不改变实际成交金额、已经收取的费用或总现金流。更换方法时需确认并重算该账号的历史持仓与盈亏，交易原始记录保持不变。

不同券商的成本价展示可能采用其他口径，例如买入均价、持仓成本、保本价或摊薄持仓成本；仅提供移动加权平均和 FIFO 不能保证与任一券商持仓页一致。逐笔实际成交金额和费用以交割单核对；如需持仓成本价和盈亏也与某券商一致，须先取得该券商计算口径，再实现相应的券商口径适配。参考：[长江证券成本价与盈亏计算说明](https://www.cjsc.com.cn/main/a/20250704/35722.shtml)。

例如先以 10 元买入 100 股，再以 20 元买入 100 股，随后以 15 元卖出 100 股，暂不计费用：移动加权平均的卖出分摊成本为 1,500 元，本笔已实现盈亏为 0；FIFO 的卖出分摊成本为 1,000 元，本笔已实现盈亏为 500 元。两种方法的实际卖出收入都是 1,500 元。

移动加权平均的计算方式：

~~~text
买入：新增成本 = 毛成交额 + 买入费用
      持仓数量 = 原数量 + 买入数量
      剩余成本 = 原剩余成本 + 新增成本

卖出：单位成本 = 卖出前剩余成本 ÷ 卖出前数量
      分摊成本 = 卖出数量 × 单位成本
      已实现盈亏 = 毛成交额 - 卖出费用 - 分摊成本
      卖出后剩余成本 = 原剩余成本 - 分摊成本

估值：持仓市值 = 当前数量 × 同币种最后成交价
      未实现盈亏 = 持仓市值 - 剩余持仓成本
      盈亏率 = 未实现盈亏 ÷ 剩余持仓成本
~~~

未实现盈亏不预扣未来卖出费用；实际卖出后，卖出费用进入已实现盈亏。

选择 FIFO 时，每次买入形成一笔含买入费用的持仓批次；卖出按买入时间从早到晚消耗批次，分摊各批次成本。卖出净收入和费用公式不变。完全卖出后剩余成本归零；一笔交易修改或撤销时按所选方法从该笔起重新计算。

## 7. 行情和股票名录

股票名录每天同步到当前账号本地数据库，覆盖沪、深、北和港股。保存代码、名称、拼音、英文名、交易所、币种、每手数量、上市状态、上市日期和退市日期。Tushare 的 stock_basic 与 hk_basic 可作为第一版接口评估对象；正式接入前确认权限、数据许可以及是否提供最后成交价。

## 9. 安全、备份和异常

~~~text
桌面界面
    ↓ 本机受保护接口
本地应用服务
    ↓ 当前账号数据库句柄
独立加密 SQLite 数据库
~~~

使用现代密码派生算法生成解密密钥；解锁后密钥只存在当前进程内存；自动锁定时关闭连接；备份文件单独加密并校验完整性；日志不记录密码、密钥或财务数据。

本地存储意味着交易和持仓不上传云端，但名录和行情仍需要联网获取。联网失败不影响查看已保存的本地数据。备份按账号加密导出；恢复时验证账号标识、密码/恢复密钥和校验值。

| 场景 | 产品行为 |
|---|---|
| 没有持仓 | 显示“记录买入”入口 |
| 搜索无结果 | 先查询公开证券目录并缓存到当前账号；目录不可用时提示检查网络或使用已缓存的股票 |
| 费用项目留空 | 阻止启用该市场模板，提示填写 0、固定金额或比例；填 0 表示确认不收取 |
| 卖出超过持仓 | 阻止保存并显示可卖数量 |
| 行情未更新 | 显示最近有效价格、日期和待更新状态 |
| 行情失败 | 显示旧价格、日期和失败原因 |
| 停牌/休市 | 显示最近有效价格及停牌/休市状态 |
| 账号切换 | 关闭数据库连接并清空页面状态 |
| 备份损坏 | 校验失败，阻止导入 |
| 重复导入 | 默认取消，允许选择覆盖或合并 |

无网络时交易录入、持仓查看、历史图表和费用配置仍可用。所有金额使用定点 decimal 计算；费用取整和价格精度按市场规则配置；删除使用撤销或软删除并保留审计记录。页面显示“仅用于记录和模拟分析，不构成投资建议”。
## 10. 验收标准

### 10.1 账号隔离与备份

- 账号 A 的交易、持仓、费用和行情在账号 B 中不可见。
- 切换账号后页面无残留数据。
- 断网可以查看已保存数据。
- 加密备份恢复后交易、费用、行情和持仓结果一致。
- 同一账号的 CNY、HKD 交易均保存本机，切换账号后两个币种的数据都不可见；币种由市场自动确定，用户不能修改。

### 10.2 股票搜索

- 沪、深、北和港股可搜索。
- A 股支持代码、中文名和拼音。
- 港股支持代码、中文名、英文名和拼音。
- 结果显示交易所和币种。
- A 股结果固定显示 CNY，港股结果固定显示 HKD。
- 历史退市股票仍能显示历史交易。

### 10.3 交易和费用

- 交易录入只需要股票、方向、数量和成交单价（每股），成交金额自动计算。
- 买入和卖出费用自动计算并逐项展示。
- 沪市、深市、北交所和港股的适用费用分别列全；每个买入/卖出项目必须明确设为 0、固定金额、比例或已包含，空白不能启用规则。
- 固定金额按笔扣减、比例按计费基数扣减，港股印花税向上取整到元；页面展示每项算式和实际扣款。
- 费用设置为 0 的项目显示“未收取”，包含在佣金中的项目显示“已包含”，都不重复扣款。
- 最低收费、取整和包含关系正确。
- 费率变更不改变旧交易。
- 部分卖出后数量、成本和已实现盈亏正确。
- 修改或撤销后相关历史持仓可以重算。
- A 股 CNY 成交和港股 HKD 成交分别显示费用、成本和盈亏，不直接跨币种相加；币种由市场自动确定。
- 移动加权平均和 FIFO 的分摊结果符合各自公式，切换方法不修改成交额与逐项费用；页面显示当前系统核算口径，不标为交易所算法。

### 10.4 行情和趋势

- 页面区分最后成交价和收盘价。
- 本月、近 3 个月、近半年、近 1 年和全部正确切换。
- 无行情时显示断点和旧价格日期。
- 停牌、休市和更新失败状态明确。
- 价格保存数据源和本机获取时间。

## 12. 成功标准

用户可以用一个本地账号完成一次买入或卖出，只输入股票、数量和成交单价（每股），系统自动计算成交金额并给出费用、成本和盈亏；另一个账号无法看到这些数据；行情更新后，用户能看到每只持仓股票的最后成交价、价格日期、数据来源和从本月到全部历史的趋势。

### 13.6 行情与历史策略

- 证券唯一编号为 `market:code`（如 `A:601162`、`HK:00700`），写入接口统一校验；`UNIQUE(market, code)` 兜底；旧编号在登录时自动迁移。
- 历史起点 2020-01-01。首次获取（本地不足 60 行）做全量回填，按 800 条/页反向分页；此后只取当日增量。
- 同步覆盖范围 = 有交易记录的股票 ∪ 未移除的关注股票。
- 收盘任务在每个市场交易日 16:30 记录当日收盘价（用当日是否存在 K 线 bar 隐式判断交易日）；服务启动时若已过 16:30 补跑一次；行情请求失败重试 3 次。
- 当日无行情时使用内存中的最新价兜底展示（`price_type=seed`，不写库）；会写入虚假行情行的 mock 机制已删除。
- 卖出与做T仅限当前有持仓的股票，卖出数量不得超过可卖数量；前端过滤 + 服务端 400 双层拦截。
- **已知偏差（记录在案，用户已判定不修）**：K 线取前复权（qfq），而成交单价是真实不复权价；发生分红送转后，图表价格轴、成本虚线与买卖标记会出现系统性偏移。若日后出现"图上价格与我的成交价对不上"，原因在此。
- **已知缺口（记录在案，用户已判定不修）**：历史已满 60 行的股票若某天服务未运行，会缺少该交易日 bar，没有缺口体检与补拉机制。

### 13.7 交互与无障碍统一规则

- 不使用原生 `confirm/alert/prompt`，统一应用内弹窗（Promise 化）。
- 弹窗不因点击遮罩关闭；Esc 关闭当前已打开的全部弹窗；打开时焦点进入弹窗内首个可聚焦元素，Tab 在弹窗内循环圈定，关闭后焦点归还触发元素。
- toast 顶部居中、单实例；破坏性操作先确认。
- 会话失效处理：除登录/注册与启动探测 `/api/me` 外，任一接口返回 401 时由 `request()` 统一触发整页重载——重载后 `/api/me` 失败即显示登录页，不再在应用内弹"请先登录"或把旧数据留在页面上。登录/注册的 401（密码错误等）跳过该处理，照常显示表单错误。
- 加载态：看板与关注首次加载显示“正在加载…”；持仓总览与复盘刷新时容器进入 `.refreshing`（半透明、`aria-busy`、禁点），避免把旧数据当成最新；更新行情期间按钮 disabled。
- **行情提示分级（2026-10-26）**：登录/打开页面触发的自动同步**不弹 toast**，顶栏文案保持原样（`已更新 / 已检查 HH:mm`，异常时仍是 `行情不完整` / `行情更新失败`）；只有手动点「更新行情」才弹「A股、港股当前时段暂无交易，沿用最近交易价」等提示。未开盘、周末与节假日都通过 `skipped_markets` 走这套展示。

### 13.10 API 契约与数据层（as-built）

- **命名**：集合用复数（`/api/trades`、`/api/reviews`、`/api/watch`、`/api/t-plans`）；子资源嵌套（`/api/watch/<id>/notes`、`/api/watch/<id>/notes/<note_id>`）；动作型端点用 `POST /api/<集合>/<动作>`（`/api/prices/sync`、`/api/prices/history`、`/api/securities/refresh`、`/api/t-plans/solve`）。
- **方法语义**：GET 一律只读；写操作走 POST/PUT/DELETE。
- **读路径不落派生列（2026-10-26）**：`recalculate_security(..., persist=False)` 供 `/api/portfolio`、`/api/board`、做T成本推演使用，`trades.total_cost / net_proceeds / realized_pnl` 只由写路径（新增/作废成交、改成本口径、收盘任务）更新；连接设 `timeout=15` + `PRAGMA busy_timeout=15000`，启动时 portfolio / board / 行情同步并发不再抢锁失败（此前 `GET /api/portfolio` 在 `UPDATE trades` 处抛 `database is locked` → 前端弹「服务器内部错误」）。
- **响应信封**：成功写操作 `{ok:true, <资源>}`（创建带 201）；DELETE 统一 `{ok:true, id}`；列表 `{ok:true, <复数名词>:[…], total, limit, offset}`（未分页的列表也带 `total`）；错误统一 `{error:"中文提示"}` + 4xx/5xx。
- **分页**：`limit` 默认 50、上限 500，`offset` ≥ 0，非法值 400。已分页：`/api/trades`、`/api/watch/<id>/notes`、`/api/audit-logs`。**有意不分页**：`/api/reviews`（前端有企业/周期/关键词三重客户端过滤与二级菜单计数，需要全集）、`/api/t-plans`（统计需要全集）、`/api/cash`（只带回最近 50 条流水供明细弹窗）、`/api/board` 与 `/api/watch`（图表需要区间内全量序列，客户端按像素降采样）。
- **金额与数量**：一律字符串传输（服务端 Decimal，三位小数），前端 `Number()` 后按同一口径格式化；比率分母 ≤ 0 时换口径而不是显示 0/`--`。
- **市值字段**：`/api/board` 的 cards、`/api/watch` 的 items、`/api/trades` 的每行都带 `market_cap`（字符串，单位亿元，公司总市值）；由 `attach_market_caps()` 批量实时拉取，失败时为 `null`（前端显示 `--`），不写库、不做每日快照。
- **鉴权**：除 `/api/health`、`/api/register`、`/api/login`、`/api/password/reset`、`/api/logout` 与静态资源外全部要求会话 cookie；账号数据按独立库文件物理隔离。
- **持仓盈亏字段**：`/api/portfolio` 的每只持仓带 `market_value`、`unrealized_pnl`（＝`total_pnl` − `realized_pnl`）、`realized_pnl`、`total_pnl`（市值 + 累计卖出净额 − 累计买入成本）、`invested_cost`；顶层另有按币种的 `realized` 与 `total_pnl` 映射（含已清仓证券）。`/api/board` 的卡片 `realized` / `unrealized` / `total_pnl` 与持仓同源。
- **做T计划载荷**：每行带 `live_unit_cost`（当前持仓每股成本）与 `live_cost_after`（按尚未执行的腿实时推演；已关闭计划为 null），`cost_before/cost_after` 仅留档；`round_trip_fee_rate` 为完整精度小数字符串。`PUT /api/t-plans/<id>` 只接受「录入实际成交价」的回填（`executed:true` + `actual_unit_price`）；旧的「标记未执行」分支已移除，传 `executed:false` 返回 400。
- **网络暴露**：`python app.py` 默认 `--host 0.0.0.0`（2026-10-16 用户要求局域网内可访问），同网段设备用 `http://<本机IP>:8765` 打开；启动时日志打印实际局域网地址并输出一条对局域网开放的 WARNING。前端全部相对路径、无硬编码 host，因此换 origin 无需改动。只给本机用时改回 `--host 127.0.0.1`。前提认知：`/api/register` 对同网段开放、传输为明文 HTTP，公共网络不开；当前 WLAN 归类 Public 且 Windows 防火墙 Public 配置文件为关闭状态，所以不需要额外入站规则。
- **库表**：账号库当前 schema 版本 7（迁移 3 = 重建 `t_plans` 放宽 `target_type` 约束；迁移 4 = `t_plans` 增加 `cost_before/cost_after` 成本快照列；迁移 5 = 新建 `cash_entries`；迁移 6 = 重建 `settings` 以容纳 `cash_started_at`；迁移 7 = 新建 `t_plan_links`）；迁移在 `init_account()` 内按 `MIGRATIONS` 顺序执行并写 `schema_version`，重复执行幂等（已在真实账号库副本上验证：行数不变、索引补齐、二次执行无变化）。金额列为 TEXT（Decimal 字符串），无 CHECK 约束，由服务端单一写入路径校验。
- **做T与资金端点**：`POST /api/t-plans/solve` 支持 `preview:true`（200、只算不落库）；`DELETE /api/t-plans/<id>` 硬删计划并解除关联、写审计；`POST /api/t-plans/<id>/link {trade_id}` 关联成交、`DELETE /api/t-plans/<id>/link?leg=known|target` 解除；`POST /api/t-plans/<id>/trades {leg, unit_price?, trade_date?}` 按计划价补录成交并关联；`GET /api/t-plans/<id>/candidates?leg=` 返回可关联成交；`POST /api/t-plans/<id>/edit {quantity, known_gross, target_type, target_value}` 修改进行中计划并重算派生值（股票/方向不可改；数量变化自动解除已知腿关联）；`POST /api/trades` 响应附带 `plan_candidates`（仅建议，不自动关联）；`GET /api/cash` 返回 `{initialized, accounts:[{currency,balance}], entries, opening:{CNY,HKD}, started_at}`（流水最近 50 条 + 期初结转）；`POST /api/cash/entries`（入金/出金，校验金额>0、出金不超余额）；`DELETE /api/cash/entries/<id>`（撤销误录，若删除入金会导致余额为负则 400）。
- **证券名录**：本地账号库优先；本地搜不到时前端显式调 `POST /api/securities/refresh` 从东方财富建议接口补全并写入账号缓存。A 股按 JYS/代码前缀归入沪深北；港股只收普通股票——补零后 5 位、以 0 开头（主板/GEM，含第二上市与介绍上市，如金山云 03896），1xxxx 窝轮、6xxxx 牛熊证、8xxxx 人民币柜台一律丢弃。不能拿接口的 `SecurityType` 判定股票：主板普通股为 19、二次上市等为 6，金山云（6）曾因此被误滤、搜索无结果，2026-10-22 改为按代码规则判定。
- **日志**：`data/server.log`（轮转 1MB×3）+ 控制台；`daily_close.py` 另有 `data/daily_close.log`。行情/名录失败一律 warning 留痕并在接口响应里降级标记，不再静默返回空。

### 13.11 资金账户（现金，2026-10-21 上线）

- **定位**：交易记录是唯一执行事实；资金账户只认「入金/出金 + 有效成交」两个来源。余额**不入库**，每次按流水与成交实时推导：`可用金额 = Σ入金 − Σ出金 − Σ买入(金额+费用) + Σ卖出(金额−费用)`。作废成交自动回滚。
- **起点机制**：首次入金/出金时写入 `settings.cash_started_at`，**起点之前的历史成交不参与可用金额推导**——避免老账户没有入金记录时重放出无意义的负数（曾显示 −¥127.9 / −HK$82,451.6 被用户否决）。未设置起点时 `GET /api/cash` 返回 `initialized:false`，卡片显示 `人民币账户 -- / 港币账户 --`。
- **资金弹窗改版（2026-10-27 确认稿落地）**：记录资金弹窗宽 640——币种、方向改为段选（隐藏 select 仍是数据源），金额后缀随币种变；金额变化实时显示「入金后可用 / 出金后可用」，出金超过可用时预览变红且保存禁用（服务端仍二次校验）。资金流水弹窗宽 640——顶部人民币/港币两个页签兼作余额与记录数，列表按币种分页；行内 时间/类型/备注/金额/操作，入金 `+`、出金 `-`（金额中性色），期初结转只读无删除；底部「＋ 记一笔」带当前币种打开记录资金弹窗；删除仍二次确认，保存/删除后余额和列表即时刷新。
- **期初结转（2026-10-26 按方案 A 落地）**：起点前已有持仓的成本（买入含费用 − 卖出净额，`opening_equity()`）作为「期初结转」计入投入口径——它是**带入的持仓成本，不是可用资金**，因此不加进可用余额（否则港股会变成 −78,321.5 的假负数），只在资金流水顶部以只读行展示（日期=起点日，备注「起算日前已有持仓」）。恒等式：`账户金额 + 持仓金额 = 净入金 + 期初结转 + 总盈亏`。`GET /api/cash` 新增 `opening:{CNY,HKD}` 与 `started_at`。
- **不允许负余额**：① 出金 > 余额 → 400；② 买入（金额+费用）> 余额 → 400「可用金额不足，请先入金」（`_create_trade` 单点校验，未来做T补录成交自动继承）；③ 删除入金记录若导致余额为负 → 400。历史数据导致余额为负时**如实标红**（`.cash-negative` 红色，不伪造 0），新操作被拦直至补录入金。
- **币种**：人民币（A 股）/港币（港股）两个独立账户，按 `trades.currency` 物理隔离，不换算、不相加。
- **界面**：持仓总览第一排「账户金额」卡只显示两行金额 + 两个文字入口「入金 / 出金」「明细」，不展示总资产/收益率/收益拆分。入金/出金弹窗（narrow）只含表单：币种/方向/金额/备注 + 保存；资金流水弹窗（wide）列表带表头（时间/类型/金额/备注/操作），五列固定轨道、所有字段左对齐（备注为空不占视觉、过长省略号截断）；≤800px 时隐藏表头、改两行网格（备注换到第二行整行显示）。列表内部滚动、底栏恒为面板全宽。交易表单费用预览末尾新增「成交后账户金额」，买入不足时红字提示并在提交前拦截（服务端 400 兜底）。
- **与做T的关系**：做T计划的手输回填不产生成交 → 不影响现金；做T「按计划价补录成交」「关联账本成交」落地后，成交本身按 §13 规则动账（补录即真实买入/卖出）。
- **迁移与接口**：migration 5（`cash_entries`）、migration 6（重建 `settings` 去掉仅允许 `cost_method` 的 CHECK）；API 见 13.10「做T与资金端点」；审计动作 `cash_entry_create` / `cash_entry_delete`，摘要形如「CNY 入金 100000.000」。
- **测试**：`test_cash_balances_guards_and_currency_isolation` 覆盖入金/出金超额/买入扣减/卖出增额/作废回滚/删除守卫/币种隔离；移动端在 375/414/620/768/1000/1440 宽度下实测无横向溢出。
